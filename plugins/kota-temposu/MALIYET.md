# maliyet: Claude Code cost statistics (optional)

Daily / weekly / monthly / yearly statistics of what your Claude Code usage would cost at API list prices, a rolling 24h / 7d / 30d view, the prompt-cache hit rate, an optional status-line segment and a small local dashboard. Part of `kota-temposu`, **off unless you install it with `--maliyet`**.

## What the numbers are (and are not)

- They are the **API-price equivalent of your token usage**: tokens read from your own Claude Code session transcripts, multiplied by the model prices in `bin/maliyet-fiyatlar.json` (input, output, cache read, cache write 5m/1h, and the advisor model's own calls). **Informational only, not a bill**: a subscription (Pro/Max/Team) is billed differently, so use the figures to compare days, projects and habits, not to predict an invoice.
- Sub-agents and Workflow agents are included and shown separately (`ana` = main conversation, `alt` = sub-agents). A model that is not in the price table is **not guessed**: its cost counts as 0 and the report ends with a `UYARI` line with the number of unpriced tokens (add the model to the price file).
- Day boundary: `Europe/Istanbul` by default; set `MALIYET_TZ` to another IANA zone (`UTC`, `Europe/Berlin`, ...) or `local`. Weeks are ISO (Mon-Sun).
- **Each API response is counted once.** Claude Code copies the earlier conversation into the transcript of a resumed session and copies the sub-agent files into the new session folder, so the same response can sit in several files (on a real machine one third of all responses were carried in more than one file). A response is identified by `message.id` (else `requestId`, else the line's `uuid`; message.id and requestId are 1:1 in real transcripts, `uuid` is per line and only the last resort). Across all files exactly one file owns a response: main conversation before sub-agent, non-fork before fork agent, earlier first/last timestamp, then path; the owner only decides the main/sub-agent split and the session, never the total. Inside one file a streamed response is written as several lines with a growing usage: the final usage counts (per-field maximum), never the sum. Results from `maliyet` 0.3.1 and older counted the copies too.
- **Re-count old days once: `maliyet --kaydet --yeniden`.** It recomputes every day (and the hourly buckets behind the 24h/7d/30d figures) for which transcripts still exist, with the rule above. **Days whose transcripts were already deleted keep their old numbers, which may still include duplicates (inflated)**: nothing is left to recount them from. The command lists such days (`UYARI: ... yeniden hesaplanamadı`); a day whose recorded sessions are only partly deleted is kept as recorded, too, because a rescan would undercount it. Without `--yeniden`, a stored day is only replaced when the scan is not lower, so the old inflated numbers stay.
- Claude Code deletes old transcripts after its retention period. The daily totals are therefore stored in `gunluk.jsonl` and kept, so monthly and yearly views keep growing after the transcripts are gone.

## Privacy

Everything is local. The tools read `~/.claude/projects/**.jsonl` (or `$CLAUDE_CONFIG_DIR/projects`), write under `~/.claude/maliyet/`, and send no usage data anywhere (no telemetry; the dashboard page loads no external resource). The one network access is the daily lira rate: `bin/maliyet_kur.py` downloads the public TCMB file `https://www.tcmb.gov.tr/kurlar/today.xml` (USD `ForexSelling`) in the background refresh, a few times a day at most, 5 s timeout; the request carries nothing of yours. No prompt, answer, title or agent description text is stored. What is stored: counts, costs, model names, **project folder names and session ids** (so the "most expensive sessions" list can name them). The files are `0600` in a `0700` directory. Do not paste or commit that directory; the dashboard `index.html` embeds the same data, treat it the same way.

## Install / uninstall

The cost statistics are part of the **default** install (team decision: the status line must show the same segments for everybody, so there is no separate switch to forget). One command per OS, run from the clone after `git pull`; it installs and updates:

```
bash plugins/kota-temposu/kur.sh                    # Linux / macOS (needs python3 and jq; macOS: brew install jq)
pwsh -File plugins/kota-temposu/kur.ps1             # Windows (PowerShell 7, or: powershell -File ...); needs a real Python 3, no jq
bash plugins/kota-temposu/kur.sh --whatif           # show the changes, write nothing   (Windows: -WhatIf)
bash plugins/kota-temposu/kur.sh --maliyetsiz       # without the cost statistics        (Windows: -Maliyetsiz)
bash plugins/kota-temposu/kur.sh --kaldir           # remove kota-temposu AND the cost statistics (the recorded history stays)   (Windows: -Kaldir)
```

`--maliyet` / `-Maliyet` (the old opt-in switch) is still accepted and means the default. The installer copies `bin/maliyet*.py`, `maliyet-fiyatlar.json` and `maliyet-panel.html` into `~/.claude/bin/`, the sub-agent row script `subagent-statusline.py` (from `plugins/ekip-ajanlari/tools`) to `~/.claude/bin/`, writes `statusLine` **and `subagentStatusLine`** into `settings.json` (a `subagentStatusLine` that is not ours is left alone), and installs a `maliyet` command in `~/.local/bin/` (add it to `PATH`). The commands it writes use the absolute path of the Python 3 it found (`python3` does not exist on Windows) and forward slashes; the self-check runs both commands exactly as written. It runs one first scan (`maliyet --kaydet`; minutes on a big history).

Run from the clone instead of copies (`kur.sh --repodan` / `kur.ps1 -Repodan`): nothing is copied into `~/.claude`; `settings.json`, the `maliyet` command (`maliyet.cmd` / `~/.local/bin/maliyet`) and the daily job (Task Scheduler / systemd / launchd) run the scripts in the claude-shared clone, and `~/.claude/kota-temposu.json` records the mode. The plugin folder has the same layout as `~/.claude` and the scripts find their siblings relative to themselves, so the output is the same in both modes; history and caches stay in `~/.claude/maliyet`. Updates arrive with `git pull`: `tools/rules_watch.py` (the session-start hook) fast-forwards the clone, runs the installer's quick self-check (`kur_ortak.py ... --sinama`) and resets the clone to the previous commit with a warning when the check fails. Trade-off: every local edit or branch switch in the clone is live at once. `--repodan` cannot be combined with `--maliyetsiz`; `--kaldir` undoes it. Details (Turkish): KURULUM.md, "Depodan çalıştırma".

**Daily record, per OS.** `maliyet --kaydet` writes the daily totals (`gunluk.jsonl`) and the hourly totals (`saatlik.jsonl`).
- Linux with systemd: a **user** timer `maliyet-gunluk.timer` (every 2 hours at :23 with up to 5 minutes of random delay, low priority, `Persistent=true`) runs it; a drop-in `maliyet-gunluk.timer.d/*.conf` that only re-sets `OnCalendar=` is backed up and removed by the installer, because it would override that schedule. With `--paylas` each run commits only when the row or the ranking changed (README, "Günlük kullanım ve sıralama"). Without systemd the installer prints an optional crontab line.
- Windows: the per-user Task Scheduler task described below.
- macOS: a per-user **launchd agent** `com.agentcrewkit.maliyet-gunluk` (`~/Library/LaunchAgents/com.agentcrewkit.maliyet-gunluk.plist`, `StartCalendarInterval` every 2 hours at :23, low priority; a Mac asleep at one of those times runs it on wake). The installer loads it with `launchctl bootstrap gui/$UID <plist>` (booting out an already loaded copy first, so a re-install is idempotent); `--kaldir` boots it out and deletes the file. Output goes to `~/.claude/maliyet/launchd.log`.
- Linux without systemd: **no timer is installed and none is needed.** The status-line background refresh (`maliyet.py --durum-yenile`, started by the status line when `durum.cache` is older than 5 minutes) writes the same `gunluk.jsonl` and `saatlik.jsonl` records (rewritten only when the content changed), so the history is kept while Claude Code is in use. A day without any Claude Code use has no new transcripts, so nothing is lost; the one gap is transcripts that Claude Code deletes on its own while the status line never ran, which the timer would not catch either.
- Joining the team usage ranking (`kur.sh --paylas --plan 100` / `kur.ps1 -Paylas -Plan 100`) makes all three jobs run `maliyet.py --kaydet --paylas`; see KURULUM.md.

The background refresh itself needs no `flock`/`nice` binary and no GNU tool: the detached child takes an exclusive lock on `durum.kilit` (`fcntl.flock` on POSIX, `msvcrt.locking` on Windows) and lowers its own priority (`os.nice(19)`), so it works the same on Linux, macOS and Windows.

To remove the history too: `rm -r ~/.claude/maliyet` (your decision, the installer never deletes it).

Windows (`pwsh -File plugins/kota-temposu/kur.ps1`, also `-WhatIf`, `-Maliyetsiz` and `-Kaldir`): installs the same files, `~\.claude\bin\maliyet.cmd` (the `maliyet` command; add `~\.claude\bin` to `PATH`) and registers the per-user Task Scheduler task `maliyet-gunluk` itself: every 2 hours at :23 (runs at the next logon when the PC was off), `pythonw.exe -I maliyet.py --kaydet`, no console window, task priority 8 (below normal), 2 h limit, **current user only, no admin rights / UAC** (the installer never touches system-wide tasks and, like the systemd branch, never registers anything when `USERPROFILE` is not the account's real profile). `-Kaldir` unregisters the task (the recorded history stays). Needs a real Python 3 (the WindowsApps `python.exe` stub is skipped); on Windows without `tzdata` the day boundary falls back to UTC+3 for `Europe/Istanbul`.
Verified on Windows 11 (PowerShell 7; the status line also under Windows PowerShell 5.1) and by the test suite on a clean Windows VM with an embeddable Python 3.13 (no bash, no jq, no tzdata). The task register/unregister snippets were run against the real Task Scheduler under a test task name. Not verified: `kur.ps1 -Kaldir` end to end, `kur.ps1` itself under Windows PowerShell 5.1, a Task Scheduler run after a reboot, a non-Istanbul `MALIYET_TZ` with `--durum` (see the note under "Status line").

## Using it

```
maliyet                  summary: rolling windows, today, last 7 days, last 4 weeks, months, years, 10 most expensive sessions
maliyet --pencere        rolling windows: last 24 h / 7 d / 30 d, with model split
maliyet --gun|--hafta|--ay|--yil [--son N]   one view, in detail
maliyet --json           all views as one JSON document
maliyet --kaydet         record daily + hourly totals (the timer does this); --yeniden recounts every day that still has transcripts
maliyet --panel [DIR]    flat JSON tables + static dashboard (default ~/.claude/maliyet/panel/index.html)
maliyet --paylas [--kuru]   record, then append today's row to raporlar/kullanim/<kisi>.md in claude-shared and regenerate SIRALAMA.md (opt-in; plain Python, spends no model tokens; see the root README, "Günlük kullanım ve sıralama")
                         (0.7.0: the same run also writes the weekly per-project summary + finished-work count to raporlar/kullanim/<kisi>.hafta.json; see maliyet_verim.py and the root README)
maliyet --help
```

Sections with no data are not printed (no empty headings). `*` after a period marks a partial one (the running period, or the period the history starts in); partial periods are left out of averages and of the busiest/cheapest pick. `önb %NN` / `isabet` is the cache hit rate: cache reads / all prompt tokens. See `docs/claude-code-cache-hygiene.md` for what lowers it.

### Status line (Linux/macOS: `statusline.sh`, Windows: `statusline.ps1`)

With the cost statistics installed, the status line (`statusline.sh`, or `statusline.ps1` on Windows) appends `önb %93 (2 kaçış)` (prompt-cache hit rate and misses of the main conversation, from the status-line JSON, Claude Code >= 2.1.251), `oturum ₺1.140 (₺19)` (the session's own `cost.total_cost_usd`, agents included), `son 7dk ₺A (₺a) · son 24sa ₺A (₺a) · 7g ₺B $C (₺b) · 30g ₺D (₺d) · ×N` (only the 7g window also shows dollars, without parentheses). Parentheses always hold the real cost on the subscription (the calibrated ratio of `maliyet_oran.py`, the same as the last action and the agent rows), and `×N` (shown once, at the end) is how many times cheaper the plan is than API list prices (`1 / katsayi` = API $ per 100 % of the weekly limit ÷ weekly plan price, about 60); both are omitted without a fresh calibration; in that case the cost segment ends with `API eşdeğeri (fatura değil)` (all amounts of the line are API list-price equivalents of your local transcripts, not what the subscription charges). Typical reasons for a missing calibration: the plan is unknown (on macOS the Claude login may live in the Keychain instead of `.credentials.json`; set `"plan_usd_monthly": 200` in `~/.claude/pace-plan.json` or run `kur.sh --paylas --plan 200`) or fewer than 4 usable quota windows in the last 7 days. The clock amount next to the time (last action) counts only the main session's own responses since its last real prompt (read incrementally from the main transcript, sidechain lines and subagent files skipped, advisor included; agents show their own cost in their rows), falling back to the `total_cost_usd` delta when the transcript is unreadable. `son Ndk` (`son 1sa20dk` from 60 min) is the `total_cost_usd` delta since the previous prompt boundary, i.e. this session including its agents, while `son 24sa/7g/30g` cover all sessions on the machine; the window is at least 5 minutes: when the current prompt is younger, it reaches back to the newest earlier prompt boundary that is at least 5 minutes old (the oldest remembered one when none is; the boundaries are kept as extra lines of the per-session state file `maliyet/tur/<session>`), and the cost is counted from there. It is omitted without a baseline or when 0. `KOTA_ISLEM_TUTARI=0` (environment, personal preference) hides the last action's amounts next to the clock. The last one comes from `maliyet.py --durum`, which **only reads a small cache file** (~20 ms) and, when the cache is older than 5 minutes, starts one detached low-priority refresh in the background; the status line never scans transcripts. Turn the segments off without uninstalling: `MALIYET_DURUM=0` in the environment, or create the file `~/.claude/maliyet/kapali` (works even if the variable does not reach the status-line process). Remove the file to turn them on again.

Windows details: `statusline.ps1` runs inside the `statusline-yerel.ps1` wrapper (one PowerShell process; no second `pwsh`). Like `statusline.sh` it makes ONE `maliyet.py --durum --girdi` call (the status-line JSON on stdin, the `python.exe` recorded in `maliyet.cmd`) and prints the three lines it returns (windows, `oturum`, last action): the per-prompt baseline and every lira amount are formatted in Python only, there is no second copy of that logic in PowerShell. There is no `fork` on Windows: the background refresh is a detached, windowless, idle-priority `pythonw` child that takes the same exclusive lock on `durum.kilit` (`msvcrt.locking`). Output is always UTF-8 bytes. Only `MALIYET_TZ=UTC` is applied to the rolling-window edge on Windows (the C runtime has no IANA zones; other zones use the system zone there, which only affects the part of a window that is completed from daily totals). Personal warnings: put them in an optional `~\.claude\bin\statusline-ek.ps1` (`param([string]$Satir)`, returns the changed line); the installer never touches it.

### Amounts are in lira

Every amount in the status lines is shown in Turkish lira at the TCMB USD selling rate (`ForexSelling` from `https://www.tcmb.gov.tr/kurlar/today.xml`), cached in `~/.claude/maliyet/kur.json`: `₺` prefix, thousands `.`, decimals `,`, two decimals under ₺100 and none from ₺100 up (`oturum ₺18.950`, `15:58 ₺2,31`); the 7g window is also shown in dollars in the same style, without parentheses (`7g ₺87.778 $1.763 (₺1.463)`). The rate is fetched only by the background refresh (never while a status line renders), when the cache is older than the latest 15:30 publication and at most once an hour; weekends, holidays and failed fetches keep the last rate. Until a rate was fetched the lines show dollars. Computation stays in USD (price table, `total_cost_usd`, the calibration); only the shown value is multiplied, so past sums are shown at today's rate. The CLI reports (`maliyet`, `--panel`) stay in dollars.

### Cost of the last action (`15:58 ₺20 (₺0,33)`)

The number after the clock is the cost of the current or last action: Claude Code's own `cost.total_cost_usd` now minus its value when the action began. An action is one user prompt (`prompt_id` in the status-line JSON). The baseline is the last total seen under the previous `prompt_id`, stored per session in `~/.claude/maliyet/tur/<session_id>` (tiny, atomic, files older than 7 days are removed); a drop of the total (`/clear`, new session) restarts at 0, so the value is never negative. Verified on this machine: `total_cost_usd` also grows with background sub-agents' requests, so an action's cost includes agents that ran or finished during it. The clock itself is plain `date +%H:%M` at render time (the line re-renders after each response), not a timestamp of the last action.

### Agent rows: API amount and real cost (ekip-ajanlari `subagent-statusline.py`)

The sub-agent panel row shows `... · 223k · ₺205 (₺15) · 15sa 5dk`: the amount at API list prices, and in parentheses what that usage really cost on your subscription plan ("gerçek", no label in the line). The last action in the main line uses the same pair (`15:58 ₺20 (₺0,33)`) with the same calibrated factor; without a calibration only the first amount is shown, no parentheses.

- **First amount (API)**: what the agent's tokens would cost at Anthropic API list prices, from its own transcript `<session>/subagents/agent-<task id>.jsonl` (the task `id` of the status-line input is the agent id). Per request it uses that request's model and token types (input, output, cache read, cache write 5m / 1h, advisor calls, Haiku 5.5 long-prompt tier), with the single price table below. `bin/maliyet_artimli.py` reads the file **incrementally** (byte offset, summed closed responses and the one still-open streamed response are kept in `~/.claude/maliyet/ajan/<agent id>.json`), so a refresh reads only the new bytes; a finished agent costs one `stat`.
- **Amount in parentheses (gerçek)**: what that usage really cost on your subscription: `API $ x W / (API $ per 100 % of the weekly limit)`, with `W = monthly plan price x 12 / 52` (what one limit week costs). Shown only while a fresh calibration exists, otherwise only the first amount.
- **Calibration** (`bin/maliyet_oran.py`, recomputed in the background refresh into `~/.claude/maliyet/oran.json`): the weekly limit arrives as an **integer** percent (verified: every logged sample is an integer), so a single step is +-0.5 %. The status line already logs every change to `~/.claude/pace-history.csv`; the cost engine keeps per-minute API $ of all local transcripts (`dk` buckets in `onbellek.json`, kept 8 days: buckets older than that are dropped on every cache write, also from files that were not re-read). The ratio is built from many short windows inside one limit week: from a point where the percent was seen to rise to the first later point at least **4 points higher** (non-overlapping), API $ spent locally in between divided by the points gained. The result is the median-guarded sum: windows outside [median/3, median x 3] are dropped (percent that rose with almost no local spend = claude.ai web/desktop or another machine), at least 4 kept windows are needed, only windows of the **last 7 days** count (older weeks showed a 10x lower ratio on the first machine measured, a different regime). `oran.json` keeps `usd_per_pct`, the windows used and dropped.
- **Plan price** (monthly USD, used for `W`): `"plan_usd_monthly": 200` in `~/.claude/pace-plan.json` wins (per-user file, same one that holds `target_hours`); else the `CLAUDE_SHARED_PLAN` / `~/.config/claude-shared/plan` setting of the usage report (100 or 200); else the account tier (only tier strings are read: `max_20x` -> 200, `max_5x` -> 100, `pro` -> 20; team default/enterprise and nothing readable mean unknown, then no `gerçek`), looked up in `~/.claude/.credentials.json` (`rateLimitTier`, `subscriptionType`), then `oauthAccount.userRateLimitTier` in `~/.claude.json` (this is where macOS has it; a team seat on a Max tier is priced by its user tier), then the macOS Keychain item `Claude Code-credentials` (2 s timeout, silent on failure, result cached as a tier string in `~/.claude/plan-tier.cache`, 1 day). If none works, set `plan_usd_monthly`.
- Limitations: usage on claude.ai web/desktop and on other machines also consumes the weekly limit but leaves no local transcript; the outlier rule removes the clearest cases, a remaining share makes `gerçek` slightly too high. The weekly limit is a vendor-internal measure, so `gerçek` is an estimate, not an invoice.

### Debug aid: the raw status-line input

Both status-line commands save the last JSON Claude Code sent them: `~/.claude/statusline-girdi.json` (main line) and `~/.claude/subagent-statusline-girdi.json` (agent rows), `0600`, overwritten atomically at every refresh. Look there to see which fields exist (cost, context, `prompt_cache`, `rate_limits`, `tasks[]` with `tokenCount`, `model`, ...). They contain paths and session ids; do not paste them unmasked.

### Dashboard

`maliyet --panel` writes `~/.claude/maliyet/panel/index.html`: open it in a browser as a file (`file://`), no server needed. Pick Gün / Hafta / Ay / Yıl; cards show the total, the average per active day, the busiest period, the cache hit rate and the advisor cost; the bars split each period into main conversation (blue) and sub-agents (orange); click a row of the table to see that period's split by model, agent type, project folder and its most expensive sessions. Re-run `maliyet --panel` to refresh it (the data is embedded, the page does not update itself). The same data is also written as `donemler.json`, `kirilimlar.json` and `ozet.json` next to it, flat tables you can load into any other tool.

## Prices

The model price table lives in **one file**, `bin/maliyet-fiyatlar.json`, with its source (the official pricing page) and the date it was verified in the `kaynak` field (re-verified 2026-10-29, including a check against Claude Code's own `total_cost_usd`: single requests matched to four decimals, cache writes at the 1-hour rate). Update it in the repo when prices change and say so in the commit. A machine can override single models without editing the packaged copy: put the same layout in `~/.claude/maliyet/fiyatlar.json` (or point `MALIYET_FIYATLAR` to a file); entries replace the packaged ones by model key. The cache key includes a hash of the effective prices, so changed prices are re-applied on the next run; to re-price (or re-count, see above) already recorded days run `maliyet --kaydet --yeniden`. Matching is by model id **prefix**, longest prefix wins.
